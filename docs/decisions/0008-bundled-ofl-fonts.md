# ADR 0008: The engine bundles OFL fonts; an installed copy wins

Date: 2026-11-10 · Status: accepted

**Context.** Presets name fonts by PostScript name and travel to every campus (Spec 1 §2), but each campus Mac has its own installed fonts, so a preset designed at one campus fell back to the machine's `fallbackFont` at another. Spec 6 §4 (P14) answers this with fonts bundled with the engine, and Adam chose DM Sans (T-6), with the italic and its weights' usual names (2026-11-10), and the installed copy winning a name clash (T-7). Shipping font files in the engine is a new resource in `engine/`, which `CLAUDE.md` asks an ADR for. **Decision.** The engine carries a small set of SIL Open Font License fonts and their licences in its resource bundle, `engine/OEngine/Resources/Fonts/`: DM Sans 4.004, roman and italic variable fonts, copied unmodified from google/fonts at a pinned commit with their SHA-256 recorded beside them. At launch, before the first raster, it registers them for its own process only, except a file whose PostScript names are installed, which it leaves unregistered and logs once. A name resolves to an installed face of that name first, then to a bundled face, by the name Core Text gives it or the usual name of its weight, and otherwise falls back and is recorded for pre-flight. Faces come from their files' own descriptors, so resolution never depends on Core Text's preference for registered fonts. **Consequences.** A preset in DM Sans renders alike at every campus with nothing installed, and a campus that installs its own copy keeps it. The bundle grows by about half a megabyte per family, adding a font is a resource change reviewed like code with its licence alongside, only OFL fonts qualify, and fonts in the media root stay deferred (Spec 4 §8). The app registers the same files for its own process to draw them (Spec 11 §8).
